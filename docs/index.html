Where vision helps a browser agent,
and where it breaks

One Qwen3-VL reads a screenshot and a DOM element table once, answers each decision from that shared prefill, and continues the same KV cache to write a field value when the chosen operation needs one. Four arms, two benchmarks, and a mechanism that did not pay off.

Evaluating a visual web agent only on MiniWoB-style pages understates what vision is worth, by roughly five-fold here. MiniWoB task success, 224 tasks per arm, scored by the environment's own reward: 38.4% / 45.5% / 43.8% / 49.1%.

04An overlay the model was not trained on overrides the text

Numbered overlays are standard practice in Set-of-Mark prompting, and this failure is silent: nothing about the output looks wrong.

05Offline corpora contain no terminal action

All 6454 Mind2Web steps are CLICK, TYPE_TEXT or SELECT, because a recorded trajectory stores one action per step and stops. The model saw DONE among its candidates and was never once shown when to pick it.

105 of 106 successful runs kept acting on a finished page until the step budget ran out. This is a property of the corpus format, not of Mind2Web. Collecting real terminal observations from a resettable environment fixes the symptom — median steps fall to 4 — and introduces a false-DONE problem of its own when those observations are taken only at the instant of completion.

06The mechanism that did not pay off

The unified decision-and-generation mechanism this project set out to show does not improve accuracy. Four of five comparisons span zero.

  • A fair autoregressive baseline had zero parse failures and zero out-of-set targets in 234 steps with a median of 20 candidates. The errors a constrained readout structurally prevents did not occur.
  • The bottleneck is perception, not expression. Both mechanisms read the same prefix and see the same candidates.
  • Fan-out needs questions to share an observation, and a browser step has 2–3. The prior work's 8.9× came from N=32. Measured here: N=1 0.99×, N=2 1.97×, N=4 2.42×.

What it does buy is decision latency, and that holds.

Reading a restricted logit is 1.8–2.4× faster than generating an action line, and accuracy does not fall. End to end it does not show: browser observation is the column next to it, and a 200 ms saving is 14% of a 1.5 s step. KV reuse for the text branch measures 3.0× at one generated token and 2.1× at eight — a fixed saving of about 110 ms, which matters most for the short values a browser actually types.

07Using it

from transformers import Qwen3VLForConditionalGeneration, AutoProcessor
from peft import PeftModel

base = "Qwen/Qwen3-VL-4B-Instruct"
model = Qwen3VLForConditionalGeneration.from_pretrained(base, dtype="bfloat16").to("cuda")
model = PeftModel.from_pretrained(model, "guanxuyu/visual-jev-browser-4b")   # arm D
processor = AutoProcessor.from_pretrained(base)

The arms are not interchangeable. A branch-readout adapter is read from one logit at an Answer: position; an autoregressive one expects to generate CLICK 4. Use vjb/model/policy.py, which selects the matching path, rather than rebuilding the prompt — the element table, the candidate symbols and the overlay all have to be constructed the way training constructed them.
